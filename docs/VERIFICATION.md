## 자동 검증

Node.js24에서 다음을 실행했습니다.

```sh
npm test
npm run check
npm run build
```

- 계정16 + 기존 API/예약14 + 인증 제공자10 + UI 보조 로직11 = **51개 통과, 실패0, 생략0**.
- JavaScript **20개 파일 문법 검사** 통과.
- 정적 `web/dist` 빌드 성공. 서버 진입점은 별도 `web/functions/`에 유지.
- `git diff --check` 통과.

계정 검증은 5명 초과 가입, 한 번 승인 후 재로그인, 아이디 중복과 대소문자 정규화, 한글·공백 비밀번호 보존, 가입 접수와 정원 경쟁, 초기화 만료·일회성·정보 비노출, 기존 세션 폐기, 로그인 중 초기화·중지, 초기화 중 두 번째 초기화, 본인 비밀번호 변경, 잘못된 제공자 UID 거부, 중단된 제공자/DB 처리의 잠금과 소유자 복구, 가입 보상 처리, 회원 CSV 허용 열·수식 방어, 기존0001 DB의 회원·예약 ID 보존과 제한된 키 전환을 포함합니다.

Google 호출 테스트는 가짜 HTTPS 응답을 이용해 고정 endpoint, 프로젝트·UID·별칭 일치, OAuth 서명·범위, 정적 오류 메시지와 비밀값 비노출을 검사했습니다. 로컬 개발 인증기는 SQLite 재접속과 PBKDF2-SHA256600,000회 검증을 시험했습니다. **Google 실제 프로젝트를 호출한 결과는 아닙니다.**

기존 예약 검증은 정확한 보안 쿠키, 본인 권한, 중복 요청, version 충돌, 취소 기한, 유효 날짜·시간, 영업시간·차단, 하루18/10건, 원자적 이동·기록, SQL 직접 입력 방어, 배치 롤백, 영속 저장, 별도 worker/별도 SQLite 연결의 동시 예약을 유지합니다. 로컬 SQLite 동시성 검증을 실제 Cloudflare D1 부하 시험으로 표현하지 않습니다.

## 브라우저 확인

Sites 관리형 미리보기와 실제 로컬 API·SQLite에서 **가상 회원·전화번호·예약만** 사용했습니다. 기존 가상 키 계정을 삭제하지 않고 아이디·비밀번호로 전환한 상태입니다.

| 흐름 | 관찰한 결과 |
|---|---|
| 가입 화면 | 이름·전화번호·아이디·비밀번호·확인 입력, 이메일 입력 없음 |
| 승인 대기 회원 | 계정 아이디와 대기 상태 표시, 예약 화면 접근 없음 |
| 승인된 회원 | 체험 버튼의 아이디·비밀번호 로그인 후 별도 승인 없이 예약 화면 접근 |
| 회원 관리 | 아이디·이름·전화번호·상태·가입일·초기화 버튼, 회원 CSV 링크 표시 |
| 운영 설정 | 기본100·최대1,000 안내, 가입 접수 설정, 공개 연락처 빈값 유지 |
| 초기화 안내 | 기존 로그인 종료·24시간·일회용·승인 및 예약 유지 설명 |
| 회원 선택 전화 예약 | 기존 회원 선택 시 이름·연락처 입력, 11월3일12:00 가상 예약 저장 성공 |
| 고객 조회 | 해당 회원의 '내 예약'에 전화로 등록한11월3일12:00–12:30 예약 표시 |
| 이미 열린 탭의 초기화 링크 | 유효하지 않은 가상 reset fragment를 즉시 주소에서 지우고 초기화 안내 화면 표시 |

실제 비밀번호 입력·초기화 완료와 병렬 요청의 상세 검증은 위 자동 테스트로 수행했습니다. 브라우저에서 새 실제 계정을 만들거나 사용자의 인증정보를 입력하지 않았습니다. 실제 제공자 재설정·실물 휴대폰·운영 HTTPS 쿠키는 배포 후 확인합니다. 개발 HTTP 프리뷰에서만 임시 쿠키 변환을 쓰며 운영 Secure/HttpOnly/SameSite 정책은 유지합니다.

## 독립 검토

구현 담당과 별도의 검토자가 인증 제공자·계정 API·SQL 마이그레이션·복구 도구·UI·최종 배포 및 소유권 문서를 검토하고 통합51개 테스트를 별도로 실행했습니다. 이미 열린 탭에서 초기화 링크의 fragment만 바뀔 때 화면 전환이 누락될 수 있던 문제를 찾아 수정했습니다. fragment 즉시 제거, 늦은 응답 무시, 더 새 링크의 흐름 보존을 보조 로직 테스트로 확인했습니다.

검토 범위에서 미해결 중대 보안·정확성 문제는 발견되지 않았습니다. 이는 무결점이나 보안 인증을 의미하지 않습니다. 제공자 변경과 DB 저장은 한 트랜잭션이 아니며 결과가 불확실하면 계정을 잠그고 문서화한 소유자 복구를 요구합니다.
