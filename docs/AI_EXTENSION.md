# 향후 AI 예약 연결

## 현재 준비된 것

예약 규칙은 화면이 아니라 API와 DB가 검사합니다. 향후 AI가 자연어를 날짜·시간으로 해석해도 같은 API를 호출하면 승인 상태, 본인 권한, 30분 단위, 휴무·시간 차단, 겹침, 하루 한도 검사를 그대로 사용할 수 있습니다. 이번 변경에 AI 모델 호출이나 유료 서비스는 들어 있지 않습니다.

| 작업 | 현재 API | 확장 때 지킬 조건 |
|---|---|---|
| 가능한 시간 확인 | `GET /api/availability?date=...` | 로그인·승인 확인, 다른 손님 이름은 전달하지 않음 |
| 예약 등록 | `POST /api/bookings` | 회원 본인 권한과 일정 규칙, 요청별 `request_id` |
| 내 예약 조회 | `GET /api/bookings` | 회원의 예약만 반환 |
| 취소 | `POST /api/bookings/:id/cancel` | 본인 여부·취소 기한·현재 version 확인 |
| 시간 이동 | 관리자 `PATCH /api/bookings/:id` | 현 정책은 관리자만 가능; 고객 AI 이동을 열려면 별도 정책 변경 필요 |

`request_id`는 같은 요청을 재시도해도 예약을 두 번 만들지 않도록 합니다. API가 성공을 반환하기 전에는 AI가 '확정'이라고 말하지 않습니다. 자리가 없어지면 최신 가능한 시간을 다시 보여줍니다.

## 권장 흐름

1. 고객이 '다음 주 화요일 오후에 가능한 시간 있어?'라고 입력합니다.
2. 한국 시간 기준으로 날짜를 해석하고 모호한 표현은 확인합니다. 과거 날짜나 임의 고객 ID를 모델이 직접 확정하지 않습니다.
3. 인증된 회원의 권한으로 가능 시간을 조회하고 후보를 보여줍니다.
4. 선택한 날짜·시간을 확인한 뒤 같은 예약 API에 전달합니다. 응답의 실제 확정 결과를 안내합니다.

초기 단계는 자연어 시간 검색과 확인 후 예약으로 시작할 수 있습니다. 나중에 자동 확정을 허용하려면 사용자가 허용한 요일·시간·예약 범위를 명시적으로 저장하고, 허용 범위를 넘어서는 요청은 다시 확인합니다.

## 아직 추가해야 하는 것

현재 브라우저의 보안 쿠키는 일반 앱용입니다. 외부 AI 에이전트에 관리자 쿠키를 복사해 주거나 CSRF 검사를 없애지 않습니다. 외부 호출이 필요하면 **회원별 제한된 위임 토큰, 허용 작업, 만료·철회, 호출 주체가 드러나는 변경 기록**을 별도로 구현해야 합니다. 현재 코드에 이런 외부 에이전트 권한이 이미 구현되어 있다고 보지 않습니다.

AI에 전체 회원 명단·비밀번호·서비스 계정·DB 직접 접근권한을 주지 않습니다. 예약 문장과 최소한의 시간 정보만 전달하고, 서버가 실제 사용자 ID를 결정합니다. 전화 통화·메시지 본문을 자동 수집하는 기능도 별도 범위입니다.

## 비용 0원 조건

현재 앱은 AI 비용이 없습니다. 향후 모델을 붙일 때도 결제수단 등록·유료 자동 전환 없이 무료 한도 내에서만 동작하게 해야 합니다. 한도를 넘거나 모델이 실패하면 일반 예약 화면을 계속 사용할 수 있게 합니다.

2026-10-30 확인 기준, Cloudflare Workers AI는 하루 10,000 neurons의 무료 할당량을 안내하지만 모델별 소모량이 다르고 일부 모델은 결제수단이 필요합니다. 이를 '무제한 무료 AI'로 해석하지 않습니다. 모델 선택·개인정보 처리·실제 요청당 사용량을 확인한 뒤 별도 도입합니다. [공식 Workers AI 가격](https://developers.cloudflare.com/workers-ai/platform/pricing/)
