# 파일럿 공유 및 예약 확인 개선

## 목표와 범위

사용자가 승인한 다섯 요청을 기존 Cloudflare Pages + D1 + Firebase 구조 안에서 처리한다. 실제 관리자 등록과 회원 가입·승인은 사용자가 확인했다. 개발자가 배포를 유지보수하고 사장님이 유일한 앱 관리자로 운영한다. 새 유료 서비스, 데이터베이스 초기화, 계정 이전은 필요하지 않다.

## 설계와 작업 순서

1. **예약 확인:** 서버의 관리자 조회가 모든 회원을 포함하는지 재현하고, 회원별 비공개와 동시 예약 보호를 회귀 테스트로 남긴다. 실제 제보 건의 날짜·세션은 아직 보지 못했으므로 원인을 확정하지 않는다.
2. **화면 갱신:** 관리자 기본 화면은 오늘부터 예약 가능한 기간 전체를 조회한다. 하루·7일 보기와 명확한 날짜 범위를 제공한다. 보이는 화면에서 30초마다, 탭 복귀 시 세션과 예약 목록을 다시 확인한다. 갱신 실패에는 이전 목록과 마지막 성공 시각을 남긴다. 같은 계정이면 입력 폼과 대화상자를 보존하고, 계정·권한 변경 시 이전 화면을 폐기한다.
3. **공유 이미지:** 회원 관리에서 공용 예약 주소와 7일·1회용 초대 주소를 각각 PNG로 만든다. 주소는 QR 위에, QR은 가운데 둔다. QR 인코딩과 캔버스 렌더링은 브라우저 안에서 수행하며 외부 QR 서비스에 토큰을 보내지 않는다. 사진 자체의 주소는 클릭 가능한 링크가 아니므로 별도 링크 복사도 제공한다.
4. **비밀번호:** 서버, 개발용 인증, 화면 검증의 최소 길이를 Unicode 문자 12개로 맞춘다. 기존 비밀번호, 공백 보존, 최대 128자는 유지한다. 원격 Firebase 정책은 실제 콘솔 설정을 알 수 없으므로 조건부 확인 사항이다.
5. **납품:** 전체 테스트, 실제 브라우저에서 폼 보존·계정 전환·목록 갱신·PNG 다운로드, PNG 스캔을 확인한다. 원격 사용자 변경을 보존해 GitHub main을 갱신하고, 기존 Pages 프로젝트에 올릴 ZIP을 제공한다.

## 검증 기준

- 같은 예약을 관리자와 예약한 회원이 조회하며 다른 회원은 조회하지 못한다.
- 동일 시간과 일일 마지막 자리를 경쟁해도 하나만 확정된다. 예약과 시간 차단도 동시에 성립하지 않는다.
- 자동 갱신은 중복 요청을 쌓지 않고 숨긴 탭·오프라인에서는 멈추며 복귀 후 재개한다.
- 새 예약은 현재 조회 범위에 포함될 때 화면에 나타나며, 범위와 마지막 확인 시각이 보인다.
- 공개 QR 및 초대 QR을 실제 디코더로 읽어 원문 URL과 동일함을 확인한다.
- 정확히 12자는 허용, 11자는 거절하고 가입·변경·재설정 경로에 적용된다.
- 실제 서비스 제보 해결 여부는 배포 후 손님 예약 날짜를 포함한 관리자 조회로 최종 확인한다.
