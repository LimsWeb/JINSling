# 반복 잠금 구현 계획

Spec: `docs/superpowers/specs/2026-11-07-recurring-closures-design.md`

## 범위 및 승인
사용자는 반복 잠금 구현과 기존 GitHub 업데이트를 요청했다. 기존 격리 worktree에서 새 기능 브랜치로 작업하며, 검증 후 GitHub main과 다운로드 배포 파일을 갱신한다. Cloudflare 실제 업로드는 연결된 권한이 없어 사용자가 수행한다. 기존 개인정보와 운영 DB에 직접 접근하지 않는다.

## Task 1: 서버·데이터 무결성
담당: recurrence_backend. 소유: web/server, web/migrations 신규 파일, 서버 단위·통합 테스트. 위 API 계약 구현, 날짜 계산/SQL 판정 동등성, 자동 추가 설치, 기존 DB 호환성, 원자적 충돌 차단, 변경 버전 및 요청 중복 방지. 관련 실패 테스트를 먼저 실행한 뒤 구현한다.

## Task 2: 운영자 UI·가이드
담당: recurrence_frontend. 소유: web/public/app.js, style.css, 새 반복 잠금 UI 모듈, guide.html/guide.mjs/guide.css. API 계약 준수. 휴대폰에서도 편집·미리보기·예외 설정을 사용할 수 있게 한다. 기존 bulk closure controls 패턴의 늦은 응답과 계정 전환 보호를 따른다.

## Task 3: 통합·배포 문서·실제 브라우저 검증
담당: root. 소유: 배포 문서, 브라우저 테스트, PDF 및 ZIP. npm test/check, 실제 Chromium에서 생성→회원 시간 차단→날짜 예외→재개 충돌→격주·매달 미리보기, 모바일/인쇄 가이드 확인. 기존 bulk 잠금 브라우저 회귀도 수행한다.

## Task 4: 독립 코드 검토·배포 파일
담당: 독립 reviewer와 root. SQL/JS 날짜 일치, 월 말·윤년·격주 기준, 오래 열린 화면, 동시에 발생하는 예약/잠금, 부분 스키마, 예외 복원, 권한, 공개 응답 개인정보를 검토한다. 중요한 문제는 회귀 테스트와 함께 해결한다. 검증한 코드로 Pages standalone worker ZIP을 만들고 GitHub main을 예상 SHA 조건으로 갱신한다.

## 검증 완료 기준
- 전체 자동 테스트와 구문 검사 통과.
- 실제 SQLite 트리거가 금지 시간의 새 예약과 이동을 거절한다.
- 반복 규칙 최초 설정이 기존 0001+0002 DB에 안전하게 적용된다.
- 브라우저에서 관리자/회원 시간 표시, 휴대폰 UI, 기존 잠금 기능 확인.
- 업로드 ZIP에 실행 가능한 _worker.js와 모든 새 정적 모듈 포함, DB/자격 증명 미포함.

## 진행 기록
- 2026-11-07: 기존 기능이 있는 깨끗한 worktree에서 `feat/recurring-closures` 시작. API 계약을 병렬 구현의 공통 기준으로 확정.
- Task 1 완료: 승인된 관리자 API, 추가 스키마/SQL 충돌 보호, 일별·월별 시간표 통합. 신규 22개 통합 테스트를 포함해 전체 118개 통과. 새 시작일·예외 생성 범위는 365일로 제한하되 저장된 무기한 반복의 수명에는 제한을 두지 않는다.
- Task 2 완료: 점심 프리셋, 반복 편집과 미리보기, 중지·재개·해제·날짜 예외, 공개 이용 가이드. 운영 설정의 다른 미저장 입력을 유지하도록 반복 목록만 갱신한다.
- Task 3 완료: 깨끗한 합성 DB의 실제 Chromium에서 반복 11개와 기존 휴무·가이드 12개 흐름 통과. 390px 화면 육안 검토. 컴파일된 Worker와 로컬 D1/workerd의 기존 DB 자동 설치 등 5개 검사 통과. 사장님용 2쪽 PDF 제작 및 렌더링 확인.
- Task 4 검토 완료: 독립 검토에서 중요도별 미해결 사항 없음. 별도 SQL/JS 날짜 대조 76,048개 일치. 최종 전체 테스트와 빌드 산출물을 바탕으로 배포 ZIP 및 GitHub 업데이트를 진행한다.
