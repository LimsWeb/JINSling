# jinSling 무료 운영 시험판 설계

## 승인된 목적과 조건

2026-10-30 대화에서 사용자는 기존 Streamlit 코드를 변경해도 좋으며, 아래 조건과 앞서 제안한 운영 보완을 반영하도록 요청했다.

- 1인샵, 동시에 고객 한 명, 예약 한 건 30분.
- 평일 하루 최대 18건. 영업시간은 잠정 09:00–20:00.
- 토요일 하루 최대 10건. 영업시간은 잠정 09:00–14:00. 일요일 휴무.
- 처음에는 사장님과 사용자를 포함한 4–5명의 시험 이용자. 주 70건은 참고치이며 프로그램의 인원/예약 제한으로 사용하지 않는다.
- 사용료와 필수 인프라 비용 0원, 로컬 서버 운영 없음. 유료 플랜·결제수단·유료 메시지·도메인 구매를 활성화하지 않는다.
- 영구 저장, 충돌 방지, 휴무/시간 차단, 전화 예약, 승인, 접근 제한, 변경 기록, 내보내기를 반영한다.

## 선택한 방향 및 대안

사용자는 비용 0원을 절대 조건으로 정하고 코드 교체를 허용했다. Cloudflare Pages Functions + D1 Free 배포용 웹앱을 만든다. 기본 pages.dev 주소를 사용하며 실제 계정 연결·배포가 완료되기 전에는 온라인 운영 완료라고 말하지 않는다.

Streamlit 유지 + 관리형 Python 호스팅은 코드 보존에 유리하지만 이 조건에서 추천한 방향이 아니다. Streamlit Community Cloud는 영업 목적으로 고객 개인정보를 처리하는 이번 서비스에 맞지 않는 약관 조건이 있어 사용하지 않는다. OpenAI Sites의 별도 호스팅 비용/인수인계 조건을 추정해 대체 배포하지 않는다. Sites preview는 개발 검증에만 사용한다.

## 구현자가 정한 변경 가능한 초기값

- 평일 09:00–20:00에는 22칸이 생기지만 하루 예약 한도 18건을 별도로 적용한다. 임의로 2시간의 휴식을 지정하지 않는다.
- 30분은 한 예약의 전체 점유시간으로 취급한다. 추가 준비시간은 0분이며 매장 확인 전 별도 시간을 가정하지 않는다.
- 영업시간, 휴무, 특정 날짜의 시간 차단, 하루 한도는 관리자 설정에서 변경 가능하다.
- 예약 공개 범위는 오늘부터 30일 후까지. 고객 취소는 시작 전까지 가능(기본 취소 마감 0분). 과거 시간으로 신규 예약/이동은 금지한다.
- 등록 계정의 기본 시험 인원 한도는 관리자 포함 5명. 관리자가 설정에서 조정할 수 있으며 주 70건과 무관하다.
- 첫 관리자는 설정 토큰으로 생성한다. 그 외에는 관리자가 발행한 초대 링크를 받아 가입하고, 승인 후 예약한다.
- 비용과 무료 실행시간 제약을 위해 인간이 고른 비밀번호 대신 256비트 무작위 접속키를 사용한다. 이는 비밀번호 해싱 강도를 낮추는 방식이 아니다. 서버에는 SHA-256 다이제스트만 보관한다. 접속키 분실 시 관리자가 재발급하고 기존 키/세션을 폐기한다.
- 서비스 명칭 기본값은 `jinSling 예약`, 운영자 연락처는 관리자가 설정한다. 실고객 공개 전에 연락처와 안내문을 확인한다.

## 범위

포함: 초대/가입/승인/이용 중지, 접속키와 세션, 고객 예약·조회·취소, 관리자 수기 예약·일정 이동·취소, 오늘/주간 일정, 휴무·영업시간·한도·시간 차단, 변경 기록, CSV 내보내기, 배포/복구 안내.

제외: 결제, 자동 문자/알림톡/이메일 발송, AI, 회원권, 포인트, 다지점/다담당자, 사진/건강기록 업로드, 방문자 통계 서비스. 알림 대신 관리자 일정 화면의 새로고침·신규 예약 확인을 제공한다.

## 구조

- 기존 Python 파일은 보존한다. 새 앱은 `web/`에 둔다.
- `web/server/`: 웹 표준 Request/Response를 사용하는 ESM API. `env.DB`는 D1 binding.
- `web/migrations/`: 스키마와 제약/트리거. 요청 처리 중 CREATE/ALTER 금지.
- `web/public/`: 한국어 모바일 우선 화면, 자체 CSS/JS, 외부 유료 리소스/추적기 없음.
- `web/functions/`: Cloudflare Pages catch-all API adapter.
- 개발 미리보기와 자동 검증은 Node 24 내장 SQLite로 실제 SQL을 실행한다. 이는 D1 클라우드에서 실제 실행한 검증과 구분한다.

## 시간·예약 불변조건

시간대는 Asia/Seoul. 날짜는 실제 유효한 `YYYY-MM-DD`, 시간은 `HH:mm`이며 예약 시작은 30분 격자다. 날짜, 시작 분, 종료 분(시작+30)을 저장한다. 한 예약은 `[start,end)` 반열린 구간을 점유한다.

확정 예약 추가/시간 이동은 DB 트리거에서 영업일·영업시간·겹침·차단·하루 최대 건수를 검사한다. 같은 날짜에서 움직일 때 자기 예약은 겹침과 한도 계산에서 제외한다. 예약 이동은 같은 행에 한 번의 UPDATE로 처리하며 실패 시 원래 예약과 변경 기록을 유지한다. 상태 변경/일반 메모 수정으로 과거 예약 기록을 다루는 것은 허용하되 과거로 새 예약하거나 이동하는 것은 금지한다.

예약 한도, 휴무, 영업시간 변경은 이미 확정된 앞으로의 예약을 무효화하면 거절한다. 시간 차단 추가 역시 기존 예약과 겹치면 거절한다. 예약 취소는 행 삭제 대신 상태 변경이다. 버전 번호로 오래된 화면에서 덮어쓰는 것을 방지한다.

## 계정과 보안

초대·접속키·세션은 각각 별도의 256비트 무작위 비밀이다. 초대는 7일 내 단 한 번 사용한다. 초대는 URL fragment로 전달하고 화면이 읽은 즉시 URL에서 제거한다. 토큰은 POST 본문에서만 교환한다. 접속키/초대는 생성 순간에만 반환하고 로그/목록/CSV에 넣지 않는다.

세션은 별도 무작위 토큰으로 생성하며 서버에 다이제스트만 저장한다. Secure, HttpOnly, SameSite=Strict, Path=/ cookie, 최대 30일. 모든 보호 API에서 사용자 상태를 다시 확인한다. 승인 전에는 본인 계정 상태만 볼 수 있다. 가입/초대 소비와 관리자 초기화는 원자적으로 한 번만 성공해야 한다.

고객은 본인 예약만 읽고 취소할 수 있다. 관리자는 전체 예약·회원·운영 설정을 관리한다. API는 역할/소유권을 서버에서 검사하며 숨긴 버튼에 의존하지 않는다. JSON 변경 요청은 Origin/Fetch-Metadata 검증과 전용 헤더를 요구한다. 로그인/가입/초기화 요청에는 제한과 일반화한 오류 응답을 사용한다. 개인정보나 키를 로그에 출력하지 않는다.

CSV는 관리자 전용이며 수식 주입을 무해화하고 UTF-8 BOM을 제공한다. 정적 UI는 사용자 입력을 textContent로 출력한다. CSP 및 보안 헤더, API no-store를 적용한다. 키를 localStorage에 저장하지 않는다.

## 사용성과 인수인계

손님: 초대 가입 → 접속키 보관 → 승인 대기 → 날짜/시간 예약 → 확정 내역 → 취소. 관리자는 회원 승인, 연락처/영업시간 설정, 신규 예약 확인, 전화 예약 등록, 일정 이동, 시간 차단, 내보내기를 휴대폰에서 처리한다.

개발 미리보기에는 가상 정보만 사용하고 실제 예약 서비스가 아님을 표시한다. 제품 코드에 기본 관리자 비밀이나 테스트 로그인 우회 경로를 넣지 않는다. 실제 Cloudflare 계정 생성/연결과 GitHub 쓰기 권한이 없으면 배포만 미완료로 보고하고 소스·설명·검증을 끝낸다. 클라우드 토큰을 대화에 붙여넣으라고 요구하지 않는다.

## 확인할 결과

1. 같은 시간의 동시 예약은 한 건만 확정된다.
2. 평일 18건/토요일 10건 한도가 실제 저장 단계에서 적용된다.
3. 꽉 찬 시간으로 이동 실패 시 원본 예약이 그대로 남는다.
4. 휴무·과거·시간 차단·폐점 뒤 종료 예약이 거절된다.
5. 계정 승인·정지·키 교체가 기존 세션에도 적용된다.
6. 타인의 예약이나 관리자 API에 접근할 수 없다.
7. 로그아웃/재접속/프로세스 재시작 후에도 예약 데이터가 유지된다.
8. 모바일 화면에서 가입·예약·취소 및 관리자 주요 기능을 실제로 조작한다.
