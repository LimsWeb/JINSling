# 사장님 사용 안내

사장님은 유일한 앱 관리자로 회원 승인과 일정을 운영합니다. 개발자가 배포·클라우드 유지보수·백업을 맡습니다. 관리자 최초 등록과 고객 가입·승인은 사용자가 실제로 확인한 상태입니다.

## 처음 한 번

전달받은 실제 운영 주소를 열고 사장님 아이디·비밀번호로 로그인합니다. 아이디는 영문·숫자·밑줄 4–32자이며 대소문자를 구분하지 않습니다. 비밀번호는 12–128자이고 한글·띄어쓰기를 사용할 수 있습니다. 긴 문장 형태로 만들고 비밀번호 관리자의 저장 기능을 이용할 수 있습니다.

처음 설정은 평일 09–20시/18건, 토요일 09–14시/10건, 일요일 휴무, 1회 30분입니다. 평일에는 가능한 시간이 22칸이지만 예약은 18건까지만 받습니다. 점심시간은 자동으로 정하지 않았으므로 실제 쉬는 시간을 직접 막아주세요.

설정의 **공개 매장 연락처**는 선택 사항입니다. 최초 등록 때 입력한 사장님의 개인 전화번호가 자동으로 공개되지 않습니다.

## 회원 가입과 한 번의 승인

1. 손님이 사이트에서 이름·전화번호·아이디·비밀번호를 입력해 가입을 신청합니다. 이메일 주소나 문자 인증은 필요하지 않습니다.
2. 사장님이 회원 관리에서 신청자를 확인하고 승인합니다. 입력된 전화번호 자체가 본인 인증을 뜻하지는 않습니다.
3. 승인된 손님은 밤에도 사장님의 추가 확인 없이 로그인하고 본인 예약을 조회·등록합니다.

**첫 가입이 아직 승인되지 않았다면** 손님은 로그인해 대기 상태를 볼 수 있지만 예약은 할 수 없습니다. 밤에 처음 신청한 사람은 사장님이 확인한 뒤 이용합니다. 매번 접속을 허가하는 구조가 아닙니다.

운영 설정에서 새 가입 접수를 닫을 수 있습니다. 기존 승인 회원은 계속 이용할 수 있습니다. 초대 링크도 선택적으로 사용할 수 있지만 기본 가입에 필수는 아닙니다. 이용 중지·가입 거절은 해당 계정의 기존 로그인도 종료합니다.

회원 등록 한도는 기본 **100명**, 설정상 **최대 1,000명**입니다. 관리자와 승인 대기·이용 중지·거절 계정도 포함합니다. 처음 4–5명 시험은 사용성을 확인하는 단계이며 전체 정원이 아닙니다. 주 70회 방문, 하루 18/10건 예약, 등록 계정 수는 각각 다른 수치입니다. 1,000명은 앱 설정 상한이며 실제 무료 처리량 보증은 아닙니다.

## 예약 주소와 QR 공유

회원 관리의 **예약 안내 · QR**을 열면 위쪽에 주소, 아래쪽에 QR이 있는 한 장의 안내 카드가 보입니다. 위쪽 주소는 실제 글자이므로 **눌러서 접속**하거나 **링크 복사**로 복사할 수 있습니다. 공용 주소 `https://jinsling-pilot.pages.dev/`는 여러 손님에게 반복해서 안내할 수 있습니다.

**한 장의 카드 모양으로 전달하려면 안내 카드 링크 복사**를 누릅니다. 받은 사람이 링크를 열면 같은 구성의 카드에서 주소를 누르거나 복사하고, QR도 사용할 수 있습니다. **안내 카드 열기**로 손님에게 보이는 화면을 먼저 확인할 수 있습니다. 카드 페이지는 로그인 없이 열리며 회원 정보는 표시하지 않습니다. 공개 안내 페이지의 제목은 `jinSling 예약`이며 운영 설정의 상호 변경을 자동으로 가져오지는 않습니다.

개별 초대가 필요하면 **＋ 1회용 초대**를 사용합니다. 초대 URL은 발급 후 **7일 동안 가입 한 번**에만 사용하므로 그 이미지를 상시 안내물로 재사용하지 않습니다. 어느 방식으로 들어와도 새 회원은 사장님의 첫 승인을 기다립니다.

공유 창에서는 **주소 또는 QR**을 누르면 해당 주소를 새 탭으로 엽니다. **링크 복사**를 누르면 주소 전체를 복사합니다. 브라우저가 복사를 막으면 주소 입력칸이 열리고 전체가 선택되므로 Ctrl+C 또는 길게 눌러 직접 복사합니다. **직접 주소 복사하기**를 열어도 됩니다. 1회용 초대 카드에는 그 사람에게 전달할 정확한 초대 주소와 실제 사용 기한이 표시됩니다.

인쇄하거나 사진으로 보내려면 **인쇄하거나 사진으로 보내기 → 이미지 저장 (PNG)**를 선택합니다. PNG를 사진으로 보내면 주소 클릭·복사 기능은 유지되지 않습니다. 문서로 전달받은 **링크가 포함된 PDF**는 주소를 클릭·복사할 수 있으므로 사진으로 변환하지 않고 파일로 보냅니다. QR은 외부 서비스로 보내지 않고 생성합니다. 실제로 배포할 안내 카드는 사장님 휴대폰으로 한 번 읽어 확인해 주세요.

## 손님과 함께 보는 예약 현황

**예약하기**의 월간 달력에 날짜별 **예약 건수·마감·휴무**가 표시됩니다. 날짜를 누르면 그날의 시간에 **예약 가능·예약됨·운영자 차단·지난 시간·일일 마감**이 표시됩니다. 사장님과 승인된 모든 회원이 동일한 예약 현황을 봅니다. 다른 손님의 이름·연락처·메모는 이 화면에 표시되지 않습니다. 전화로 받은 수기 예약도 같은 시간을 막습니다.

날짜와 시간 화면도 **30초마다**, 탭으로 돌아왔을 때, 새로고침을 눌렀을 때 갱신합니다. 선택한 시간이 먼저 예약되면 선택이 해제되며 작성하던 메모는 남습니다. 연결 문제로 최신 현황을 확인하지 못하면 시간 선택을 잠시 막고 다시 확인하도록 안내합니다.

예약 확정창을 연 사이에 같은 시간이 예약됐다면 **다른 시간 선택**을 눌러 돌아갑니다. 서버에서 먼저 저장된 한 건만 확정되며, 같은 시각이라도 날짜가 다르면 별도 예약입니다. 날짜·요일·연도를 시간 목록과 확정창에서 함께 확인해 주세요. 취소한 예약의 시간은 다음 현황 갱신 때 다시 열립니다.

## 비밀번호를 잊어버렸다면

회원 관리에서 본인인지 확인한 뒤 **비밀번호 초기화**를 누릅니다. 화면에 한 번 나오는 링크를 그 회원에게 직접 전달합니다. 자동 문자·이메일은 보내지 않습니다.

링크는 발급 후 24시간 동안 한 번 사용할 수 있습니다. 링크를 받은 회원이 새 비밀번호를 정합니다. 사장님은 원래 비밀번호나 새 비밀번호를 볼 수 없습니다. 발급 즉시 그 회원의 기존 로그인이 종료되며, 초기화를 마칠 때까지 이전 비밀번호로 로그인할 수 없습니다. 승인 상태와 예약 기록은 그대로입니다.

새 링크를 다시 발급하면 이전 링크는 무효가 됩니다. 초기화 처리 중이라는 안내가 나오면 먼저 끝날 때까지 기다립니다. 인증 서비스 오류 뒤에도 잠금이 계속되면 DB를 임의로 지우지 말고 [소유자 복구 절차](DEPLOY_FREE.md#계정-분실과-중단된-비밀번호-처리-복구)를 따릅니다.

로그인한 회원은 계정 메뉴에서 현재 비밀번호를 확인하고 직접 변경할 수도 있습니다. 변경하면 다른 기기에서 사용하던 기존 로그인은 종료됩니다. 사장님 본인 비밀번호를 잃어버린 경우에는 유지보수 담당 개발자에게 복구를 요청합니다. 개발자가 운영 클라우드 권한으로 문서화된 복구 절차를 진행합니다.

기존 접속키 방식으로 이미 만든 계정은 그 키로 한 번 로그인해 아이디·비밀번호를 정하면 됩니다. 같은 회원번호·승인 상태·예약 기록을 유지하며 전환 후에는 예전 키를 사용할 수 없습니다.

## 전화 예약과 하루 업무

관리자 일정의 기본 화면은 **다가오는 예약**이며 오늘부터 예약 가능 기간 전체의 고객 예약을 보여줍니다. 필요하면 **하루** 또는 **7일** 범위와 날짜를 선택합니다. 고객 예약이 보이지 않을 때는 현재 조회 범위에 그 예약 날짜가 들어 있는지 확인합니다. **내 계정 예약**은 관리자 본인 계정에 연결된 예약만 보여주는 별도 메뉴입니다. 이미 가입한 회원은 전화 예약의 목록에서 선택하면 그 회원에게 연결된 예약으로 등록할 수 있습니다. 회원이 아닌 전화 손님도 이름과 전화번호로 수기 예약할 수 있습니다. 비회원 수기 예약은 나중에 같은 전화번호로 가입했다고 자동으로 합쳐지지 않습니다.

휴식·개인 일정은 운영 설정에서 시간을 차단합니다. 특정 날짜 전체를 쉬려면 그날 영업시간 전체를 차단합니다. 다른 고객 예약과 겹치는 시간에는 전화 예약도 들어가지 않습니다. 이미 예약된 시간을 막으려면 해당 예약을 먼저 이동하거나 취소합니다.

일정은 화면이 보일 때 **30초마다 갱신**하며 마지막 동기화 시각을 표시합니다. 다른 탭에서 돌아오거나 연결이 복구될 때도 최신 상태를 확인합니다. 자동 갱신 중 작성하던 입력은 유지하고, 연결 실패 시 기존 목록을 남겨둡니다. 다른 계정으로 로그인된 것이 확인되면 이전 관리자 화면과 초기화 창을 닫습니다.

문자·카카오 알림을 자동으로 보내지는 않습니다. 일을 시작할 때 조회 범위와 마지막 동기화 시각을 확인해 주세요. 예약이 계속 보이지 않으면 동작·시각을 개발자에게 전달합니다. 기존 운영 예약 누락 제보의 실제 원인은 아직 확정하지 않았습니다.

## 예약 변경과 취소

사장님은 예약을 선택해 날짜·시간을 이동하거나 취소할 수 있습니다. 다른 예약이 있는 시간, 쉬는 시간, 하루 한도가 찬 날짜로 옮기면 변경이 거절되고 원래 예약이 유지됩니다. 오래 열어 둔 화면에서 충돌 안내가 나오면 최신 일정을 확인한 뒤 다시 처리합니다.

손님은 본인 예약을 확인하고 설정된 취소 기한까지 취소할 수 있습니다. 기본 취소 기한은 예약 시작 전입니다. 고객의 날짜·시간 이동은 사장님이 처리합니다. 취소는 삭제 대신 기록으로 남고, 변경 기록에서 담당자와 시각을 확인할 수 있습니다.

요일별 영업시간·정기 휴무·하루 예약 한도도 설정에서 바꿉니다. 이미 있는 예약을 무효로 만드는 변경은 거절됩니다. 하루 한도에는 이미 방문 시간이 지난 확정 예약도 포함됩니다. 오늘 확정 예약 수보다 낮게 한도를 바꾸려면 다음 날 적용합니다. 시간 차단은 앞으로 365일까지 등록·조회합니다. 현재 화면의 종료 시각 입력은 23:30까지입니다.

## 회원 정보와 기록 보관

회원 관리에서 이름·전화번호·아이디·가입일·승인 상태·비밀번호 초기화 상태를 볼 수 있습니다. 회원 CSV를 내려받아 **사장님 본인의 비공개 Google Sheet**에 가져올 수도 있습니다. 비밀번호·초기화 링크는 CSV에 들어가지 않습니다. 시트를 수정해도 앱 회원 정보가 바뀌지는 않습니다.

예약 CSV도 별도로 제공합니다. CSV는 업무 확인용이며 계정·권한·변경 기록까지 복원하는 전체 백업은 아닙니다. 운영 백업과 클라우드 유지보수는 개발자가 담당합니다. 사장님이 문제를 설명하기 위해 실제 고객 명단 전체를 따로 보낼 필요는 없습니다. 문제가 있으면 오류가 발생한 동작·시각·개인정보를 가린 화면을 전달합니다.

## 첫 4–5명 시험

최초 관리자 등록과 고객 가입·승인은 확인했습니다. 남은 시험은 휴대폰에서 재로그인 → 예약 → 같은 날짜 조회 → 화면을 닫고 다시 조회를 이어서 해보는 것입니다. 공유 PNG도 실제 휴대폰으로 읽어봅니다. 사장님이 로그인하지 않은 시간에도 승인된 회원이 이용되는지 확인합니다. 서로 같은 시간을 골랐을 때 하나만 확정되는지, 전화 예약·시간 차단·이동·취소가 실제 업무와 맞는지 확인합니다. 초기화 링크가 한 번만 작동하는지도 함께 확인합니다.

가상 예약인지 실제 방문 예약인지 참여자끼리 정해 혼동을 막습니다. 개발 미리보기의 체험 계정은 운영 사이트에 포함되지 않습니다. 이번 확인은 로컬 브라우저와 가상 데이터로 진행했으며 실물 휴대폰 시험은 남아 있습니다. Firebase 콘솔의 실제 최소 길이도 아직 확인하지 않았으므로, 15자로 남아 있다면 개발자가 12자 정책을 맞추고 실제 인증을 확인합니다. 예약 조회와 휴대폰 확인을 마친 뒤 사용 범위를 넓힙니다.
