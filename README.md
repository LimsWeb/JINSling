# jinSling — 1인샵 예약 웹앱

사장님 한 분이 회원 승인, 온라인·전화 예약, 휴무와 시간 차단을 관리하는 한국어 예약 앱입니다. 새 앱은 `web/`에 있으며 기존 Python 시제품도 보존했습니다. 아이디·비밀번호로 가입하고 **처음 한 번 승인받으면 이후에는 언제든 직접 로그인**합니다. 이메일·문자 인증은 요구하지 않습니다.

## 기본 운영 조건

| 항목 | 초기값 |
|---|---|
| 담당자 / 점유시간 | 한 명 / 한 예약 30분 |
| 월–금 | 09:00–20:00, 하루 최대 18건 |
| 토요일 | 09:00–14:00, 하루 최대 10건 |
| 일요일 | 휴무 |
| 첫 사용 시험 | 관리자 포함 4–5명으로 시작 권장; 시스템 한도가 아님 |
| 등록 계정 한도 | 기본 100명, 관리자 설정으로 최대 1,000명 |
| 예약 범위 | 오늘부터 30일 후까지 |
| 고객 취소 | 시작 전까지 |

평일 영업시간에는 22개의 가능한 시작 시간이 있지만 예약 한도는 18건입니다. 임의의 점심시간을 가정하지 않으며 관리자가 실제 휴식시간을 차단합니다. 시간과 한도는 별도로 변경할 수 있습니다. 주 70건은 프로그램 제한이 아닙니다.

## 실행과 배포

개발 확인에는 Node.js 24 이상이 필요합니다. 앱 자체에는 npm 런타임 의존성이 없습니다.

```sh
npm test
npm run build
npm run dev
```

`npm run dev`는 가상 계정을 사용하는 개발 미리보기입니다. 운영 중 PC를 켜 둘 필요가 없습니다. 배포 대상은 **Cloudflare Pages Functions + D1 Free**, 비밀번호 인증은 **Firebase Authentication Spark**입니다. 실제 계정 연결·DB 생성·인증 서비스 확인·배포는 별도로 완료해야 합니다.

## 주요 기능

아이디·비밀번호 가입과 로그인, 일회 승인, 가입 접수 열기/닫기, 회원 이용 중지, 비밀번호 변경·초기화, 고객 본인 예약, 회원을 선택한 관리자 전화 예약, 일정 이동·취소, 중복 예약 및 하루 한도 검사, 휴무·시간 차단, 변경 기록, 회원·예약 CSV 내보내기.

DB 제약과 트리거가 예약 충돌을 막습니다. 예약 변경 실패 시 원래 예약을 유지하고, 취소는 기록으로 남깁니다. 고객 정보는 인증 후 본인 또는 관리자에게만 반환합니다.

## 비용 경계

Cloudflare Free, Firebase Spark, 제공되는 pages.dev 주소로 구성합니다. 유료 플랜 전환·결제수단 등록·유료 문자 발송을 하지 않습니다. 무료 한도를 넘으면 요청이 제한될 수 있으며 무료 정책의 영구 유지는 보장할 수 없습니다. 실제 클라우드 인증·요청·CPU 사용량은 첫 배포 후 확인합니다. 현재 코드의 1,000명 설정 상한은 처리량 보증이 아닙니다.

사장님이 Cloudflare·Firebase·운영 배포 저장소·백업을 소유합니다. 개발자는 가상 데이터와 개발 저장소만 사용합니다. 개발자가 실제 서버를 마음대로 배포할 수 있으면 DB를 읽는 코드를 넣을 수 있으므로 배포 권한까지 분리해야 합니다. 비밀번호 원문은 사장님 화면·DB·CSV 어디에도 저장하거나 표시하지 않습니다. 운영 DB에는 이름·전화번호·아이디·승인 상태·예약 등을, 인증 서비스에는 비밀번호 검증 정보를 보관합니다.

Firebase는 내부적으로 이메일 형태의 식별자를 사용하므로 앱이 아이디를 배달되지 않는 `.invalid` 주소로 변환합니다. 실제 이메일 계정은 필요하지 않습니다. 이 별칭의 허용 여부와 실제 가입·로그인·초기화는 **사장님 Firebase 프로젝트를 연결한 뒤 확인해야 하는 배포 조건**입니다. 개발 미리보기의 성공만으로 실제 서비스 연결을 검증했다고 보지 않습니다.
