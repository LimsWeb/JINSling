# jinSling AI Lab

사장님의 일정·회원 관리와 회원의 예약을 채팅으로 시험하는 **독립 실험 프로젝트**입니다. 같은 저장소 안의 `ai-lab/`에 있지만 실행, 빌드, 배포, 데이터베이스가 운영 앱 `web/`과 분리되어 있습니다. 운영 회원·예약을 가져오거나 변경하는 연결은 없습니다.

## 시험할 수 있는 것

| 계정 | 일반 화면과 채팅에서 할 일 |
|---|---|
| 가상 사장님 | 일정·회원 조회, 회원 대신 예약, 예약 취소, 하루·오전·오후 잠금과 해제, 회원 승인·이용 중지 |
| 가상 회원 A/B | 빈 시간 조회, 본인 예약과 취소 |
| 승인 대기 회원 | 승인 대기 화면, 사장님의 승인 후 회원 기능 |

변경은 날짜·시간·대상·작업을 표시하고 **확인하고 실행**을 눌러야 저장합니다. 확인 요청은 계정에 묶이며 5분 후 만료됩니다. 저장 직전에 권한, 상태, 예약 충돌과 일일 한도를 다시 검사합니다. 같은 확인을 여러 번 보내도 한 번만 반영합니다.

현재 계정은 네 개의 고정된 가상 계정입니다. 전화 알림, 실제 고객 가입, 기존 데이터 이전, 자연어로 운영 규칙을 임의 변경하는 기능은 이번 실험 범위에 포함하지 않습니다.

## 두 가지 대화 모드

- **모의 대화 (`simulation`, 기본값):** 정해진 한국어 표현을 해석합니다. 외부 모델 호출 없이 확인·예약·권한 흐름을 점검합니다. 실제 AI의 이해 성능으로 소개하지 않습니다.
- **실제 AI (`workers`):** Cloudflare Workers AI의 `@cf/google/gemma-4-26b-a4b-it`가 요청을 제한된 작업 형식으로 바꿉니다. 서버가 결과를 검증하고 조회하거나 확인 요청을 만듭니다. 모델에 SQL·인증정보·DB 권한을 주지 않습니다.

모델은 문장마다 한 번만 호출합니다. 이전 대화 전체를 기억하는 비서는 아닙니다. 모호한 문장은 날짜·시간을 다시 지정해야 합니다. 실패·한도 초과 때는 안내를 표시하며 일반 예약 화면을 계속 사용할 수 있습니다.

## 개발자가 컴퓨터에서 확인하기

Node.js 24 이상이 필요합니다.

```bash
cd ai-lab
npm ci
npm test
npm run dev
```

출력된 `http://127.0.0.1:4177/`을 열면 가상 계정 바로 열기 버튼이 나옵니다. 개발 서버는 `127.0.0.1`에만 열리고 메모리 DB를 사용합니다. 종료하면 실험 데이터가 사라집니다. 배포 파일에는 바로 로그인하는 개발 기능이나 입장 코드가 포함되지 않습니다.

## 무료 클라우드 실험실 만들기

운영 사이트와 다른 **Cloudflare Pages 프로젝트 + D1 데이터베이스**를 만듭니다. 배포 후 컴퓨터를 계속 켜 둘 필요는 없습니다.

### 1. 별도 Pages와 DB

1. 개발자가 `npm run build`를 실행합니다. 업로드 대상은 `ai-lab/dist`의 내용입니다.
2. Cloudflare **Pages 파일 업로드**에서 새 프로젝트를 만듭니다. 권장 이름은 `jinsling-ai-lab`이며 이미 사용 중이면 다른 이름을 선택합니다.
3. 새 D1 데이터베이스 `jinsling-ai-lab-db`를 만듭니다. 운영용 `jinsling-db`를 선택하지 않습니다.
4. 새 DB에 [migrations/0001_lab.sql](migrations/0001_lab.sql)을 한 번 적용합니다. 내용은 가상 사장님과 세 가상 회원뿐입니다.
5. 새 Pages의 D1 binding 이름을 **`LAB_DB`**로 지정하고 새 실험 DB를 연결합니다.

설정 파일을 쓰려면 [wrangler.example.jsonc](wrangler.example.jsonc)를 `wrangler.jsonc`로 복사하고 **새 실험 DB의 ID**를 넣습니다. CLI 초기화 명령은 `wrangler d1 migrations apply jinsling-ai-lab-db --remote`입니다. 계정·DB ID는 저장소에 미리 채워 두지 않습니다.

서버는 `LAB_STAGE=sandbox`와 DB의 실험실 표식을 먼저 확인합니다. 표식이 없는 DB는 자동 초기화하거나 변경하지 않습니다. 이 방어 장치는 처음부터 올바른 새 DB를 고르는 절차를 대신하지 않습니다.

### 2. 환경 변수와 입장 코드

새 실험 Pages 프로젝트의 **Production** 환경에 넣습니다.

| 이름 | 형식 | 값 |
|---|---|---|
| `LAB_STAGE` | Text | `sandbox` |
| `AI_MODE` | Text | `simulation` |
| `FREE_PLAN_CONFIRMED` | Text | `false` |
| `LAB_OWNER_CODE` | Secret | 새 사장님 체험용 무작위 코드 |
| `LAB_MEMBER_CODE` | Secret | 사장님 코드와 다른 새 회원 체험용 무작위 코드 |

두 코드는 각각 최소 24자이고 서로 달라야 합니다. 다음 명령으로 충분히 긴 코드 두 개를 만듭니다. 출력된 **값만** 해당 Secret에 저장합니다. 코드·터미널 출력은 GitHub, 채팅, 공유 이미지에 올리지 않습니다.

```bash
npm run keys
```

변수·binding을 저장하고 실험 프로젝트에 새 배포를 만듭니다. 회원 코드는 가상 회원 A/B/승인 대기 계정에 공통으로 쓰는 **체험용 접근 방식**입니다. 실제 고객 인증을 대신하지 않습니다. 사장님 코드는 개발자와 해당 체험자만 사용합니다.

### 3. 실제 AI는 무료 요금제를 확인한 뒤 켜기

2026-11-07 공식 문서 확인 기준 Workers AI 무료 할당량은 **하루 10,000 neurons**, 초기화는 **00:00 UTC / 오전 9시 한국 시간**입니다. Workers **Free**에서 한도를 넘으면 요청이 실패합니다. Workers Paid에서는 초과 사용료가 발생할 수 있습니다. 새 프로젝트를 만들었다고 계정 요금제가 무료로 바뀌지는 않습니다.

1. 해당 Cloudflare 계정이 **Workers Free**인지 개발자가 확인합니다. 유료 업그레이드·선불 크레딧·결제 연결은 설치 단계에 없습니다.
2. 실험 Pages에 Workers AI binding을 추가하고 이름을 **`AI`**로 지정합니다.
3. `FREE_PLAN_CONFIRMED=true`, `AI_MODE=workers`로 바꾸고 **실험 프로젝트만** 재배포합니다.
4. 화면의 **실제 AI 연결 모드**를 확인하고 가상 데이터로 품질과 사용량을 관찰합니다.

`FREE_PLAN_CONFIRMED`는 개발자가 요금제를 확인했다는 설정입니다. 앱이 Cloudflare 결제 상태를 조회하거나 비용을 강제로 0원으로 만드는 기능은 아닙니다. 무료 조건을 확인하지 못하면 모의 모드를 유지합니다. 유료 공급자로 자동 전환하는 코드는 없습니다.

앱 자체에도 **전체 하루 30회 / 계정별 하루 10회**의 모델 호출 제한을 두었습니다. 입력 최대 512자, 짧은 구조화 출력으로 제한하고 실패한 요청도 호출 예산에 포함합니다. 다른 프로젝트의 사용량과 모델별 neurons 소비가 있어 호출 횟수만으로 무료 잔량을 보장하지 않습니다.

공식 근거와 응답 형식은 [PROVIDER_NOTES.md](PROVIDER_NOTES.md)에 있습니다.

## 권한과 데이터 경계

- 계정·역할은 서버 세션에서 결정합니다. 모델이 관리자라고 주장해도 권한은 바뀌지 않습니다.
- 회원은 본인 예약만 보고 변경합니다. 공통 시간표는 이름 없이 예약·잠금 여부만 보여 줍니다.
- 세션·확인 요청·변경 기록은 실험 D1에만 보관합니다. 운영 DB·Firebase 계정·관리자 토큰을 복사하지 않습니다.
- 계정 중지, 만료, 그 사이의 예약 변경·선점이 있으면 이전 제안은 실행되지 않습니다.
- D1 제약과 트리거가 같은 자리의 동시 예약과 잠금·예약 충돌을 막습니다.
- 실제 이름·전화번호·병력·고객 메모를 입력하지 않습니다. 모델 요청/응답 본문은 앱 로그에 기록하지 않습니다.

## 운영 앱에 제안하기 전

1. 사장님이 가상 계정으로 일정 조회, 잠금·해제, 회원 승인·중지를 직접 수행합니다.
2. 회원 A/B가 같은 시간을 동시에 선택해도 하나만 확정되는지 확인합니다.
3. “오후쯤”, “다음 주”처럼 모호한 요청, 과거 날짜, 휴무일을 실제 모델로 확인합니다.
4. 권한을 넘는 요청과 명령 무시 문장을 보내도 서버가 거절하는지 확인합니다.
5. AI가 꺼졌거나 한도에 도달해도 일반 예약 화면을 사용합니다.
6. 취소·회원 변경 대상과 확인 화면을 사장님이 이해하는지 듣고 문구를 다듬습니다.

통과 후 운영 인증·현재 예약 규칙과 연결하는 변경을 별도로 검토합니다. 실험실을 운영 ZIP에 합쳐 배포하는 방식으로 도입하지 않습니다.

## 검증 범위

자동 테스트와 로컬 브라우저 검증은 실제 SQLite와 가상 계정을 사용합니다. 모델 응답·오류 테스트는 명시적인 공급자 대역을 사용합니다. 실제 AI binding을 연결해 한국어 품질·지연·사용량을 확인하는 작업은 별도 실험 배포의 확인 항목입니다.
